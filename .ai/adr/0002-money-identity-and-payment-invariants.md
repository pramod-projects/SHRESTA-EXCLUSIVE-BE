# ADR 0002: Money, Identity, and Payment Invariants

## Status

Accepted

## Decision

All persistent IDs use UUID v4 generated by PostgreSQL. All monetary values use signed 64-bit integer paise. Razorpay webhooks are the only authoritative payment confirmation source. Order items freeze product name, unit price in paise, and Cloudinary public_id at creation.

## Rejected

- Integer auto-increment IDs, because they leak scale and complicate future distributed writes.
- Float, double, decimal strings, and rupee internal units, because financial correctness must be deterministic.
- Frontend payment callbacks as order truth, because the browser is not trusted infrastructure.

## Consequences

- Database checks and Java value objects must prevent invalid money values.
- API contracts must name paise explicitly.
- Payment and order flows must be idempotent at API, webhook, and database layers.
